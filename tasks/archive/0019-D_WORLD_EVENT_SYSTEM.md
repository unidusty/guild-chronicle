# 0019-D — 랜덤 세계 이벤트 시스템 구축

**버전**: 0019-D  
**날짜**: 2026-08-03  
**상태**: todo

---

## 목적

0019-D에서는 길드 내부 시스템인 귀환 보고, 재정, 전리품 경제 기반 위에
**랜덤 세계 이벤트(World Event)** 시스템을 구축한다.

세계 이벤트는 길드 외부에서 발생하는 사건으로,
게임 세계가 플레이어와 무관하게 변화하고 있다는 느낌을 제공한다.

이번 업데이트의 목표는 다음과 같다.

- 세계 이벤트 데이터 구조 구축
- 이벤트 발생 조건 및 확률 처리
- 이벤트 지속 기간 및 종료 처리
- 활성 이벤트 관리
- 일부 기존 시스템과 실제 효과 연동
- 다음 날 시작 시 플레이어에게 이벤트 발생 및 종료 사실 알림

이번 작업은 세계 이벤트의 **기반 시스템**을 만드는 작업이다.
복잡한 연쇄 사건이나 지역별 정치 변화는 구현하지 않는다.

---

## 구현 범위

### 1. 세계 이벤트 데이터 구조

세계 이벤트 정의와 실제 발생한 이벤트 인스턴스를 구분한다.

필요한 타입 예시

- `WorldEventDefinition`
- `ActiveWorldEvent`
- `WorldEventType`
- `WorldEventEffect`
- `WorldEventCondition`
- `WorldEventNotification`

정확한 타입명과 구조는 기존 프로젝트의 타입 및 데이터 관리 원칙에 맞게 정한다.

세계 이벤트 정의에는 최소한 다음 정보를 포함할 수 있어야 한다.

- 이벤트 ID
- 이벤트 이름
- 설명
- 이벤트 종류
- 기본 발생 가중치 또는 확률
- 발생 조건
- 최소 지속 기간
- 최대 지속 기간
- 중복 허용 여부
- 적용 효과
- 시작 알림 문구
- 종료 알림 문구

활성 세계 이벤트에는 최소한 다음 정보를 포함할 수 있어야 한다.

- 활성 이벤트 ID
- 이벤트 정의 ID
- 시작 날짜
- 종료 예정 날짜 또는 남은 기간
- 현재 적용 중인 효과
- 관련 기록 정보

---

### 2. 세계 이벤트 목록

기본 이벤트를 데이터 기반으로 구성한다.

초기 구현 대상 예시

- 왕국 축제
- 몬스터 증가
- 흉년
- 풍년
- 상인 방문
- 귀족 의뢰 증가
- 국경 분쟁
- 전염병

이벤트 정의는 한 곳에서 관리한다.

이벤트별 조건과 효과를 UI 또는 시뮬레이션 코드 여러 곳에 중복 작성하지 않는다.

---

### 3. 이벤트 발생 시점

현재 프로젝트의 공식 시간 진행은
**길드 홀의 ‘오늘 업무 종료’ 처리**를 기준으로 한다.

따라서 세계 이벤트 판정은 별도의 실시간 타이머가 아니라
기존 `processDayEnd` 또는 이에 연결된 일일 시뮬레이션 흐름에서 처리한다.

권장 흐름

1. 오늘 업무 종료
2. 기존 일일 처리 수행
3. 세계 이벤트 지속 기간 감소 및 종료 판정
4. 신규 세계 이벤트 발생 판정
5. 다음 날짜 상태 확정
6. 일일 운영 보고서 또는 다음 날 알림에 세계 이벤트 결과 포함

정확한 삽입 순서는 기존 `processDayEnd` 구조를 확인하여
기존 시스템과 충돌하지 않는 위치에 배치한다.

하루에 여러 신규 이벤트가 무제한으로 발생하지 않도록 한다.

초기 기본값은 **하루 최대 신규 세계 이벤트 1개**를 권장한다.

---

### 4. 이벤트 발생 조건

이벤트는 단순 완전 무작위가 아니라
정의된 조건을 만족할 때만 후보가 될 수 있도록 설계한다.

조건 예시

- 특정 계절
- 특정 길드 명성 범위
- 특정 길드 자금 범위
- 특정 시설 보유 여부
- 현재 활성 이벤트와의 충돌 여부
- 동일 이벤트 최근 발생 여부
- 최소 게임 경과 일수

이번 업데이트에서는 필요한 최소 조건만 실제 구현해도 된다.

다만 향후 조건 확장이 가능하도록 구조를 설계한다.

---

### 5. 이벤트 중복 및 반복 방지

다음 규칙을 적용한다.

- 동일 이벤트가 이미 활성 상태라면 다시 발생하지 않음
- 중복 불가 이벤트끼리는 동시에 활성화하지 않음
- 종료 직후 동일 이벤트가 바로 재발하지 않도록 최근 기록 또는 쿨다운 고려
- 상반된 이벤트가 동시에 활성화되지 않도록 충돌 그룹 또는 차단 조건 지원

예시

- 풍년과 흉년 동시 활성화 금지
- 왕국 축제와 전염병의 동시 허용 여부는 정의 데이터에서 결정
- 몬스터 증가 이벤트가 중복해서 누적되지 않도록 처리

이번 작업에서는 간단한 중복 방지 규칙만 적용해도 되지만,
임의의 `if`문을 여러 위치에 추가하지 않고 데이터 기반 확장이 가능해야 한다.

---

### 6. 이벤트 지속 기간

세계 이벤트는 시작 즉시 끝나지 않고 일정 기간 지속된다.

각 이벤트 정의에 따라 지속 기간을 계산한다.

예시

- 왕국 축제: 2~4일
- 상인 방문: 1~2일
- 몬스터 증가: 4~8일
- 풍년·흉년: 7~15일
- 국경 분쟁: 5~12일
- 전염병: 6~14일

위 수치는 구현 예시이며,
실제 초기 수치는 현재 게임 밸런스에 맞게 조정할 수 있다.

지속 기간은 게임 날짜 기준으로 감소한다.

남은 기간이 0이 되면 이벤트를 종료한다.

종료 시

- 활성 이벤트 목록에서 제거
- 이벤트 효과 해제
- 종료 알림 생성
- 필요 시 세계 연대기 기록

을 처리한다.

---

### 7. 이벤트 효과 구조

세계 이벤트는 다음 시스템에 영향을 줄 수 있도록 설계한다.

- 의뢰 발생
- 의뢰 보상
- 전리품 가치
- 창고 판매
- 길드 재정
- 모험가 모집
- 지역 위험도

이번 작업에서는 모든 효과를 실제 구현할 필요는 없다.

최소한 일부 이벤트는 실제 효과를 가져야 한다.

권장 실제 연동 대상

#### 왕국 축제

- 창고 판매가에 일시적인 판매 보정 적용
- 또는 일부 전리품 판매 수익 증가

#### 몬스터 증가

- 향후 의뢰 생성 시스템에서 사용할 몬스터 관련 modifier 저장
- 현재 자동 의뢰 생성이 없다면 지역 위험도 또는 세계 상태 modifier만 실제 보존

#### 흉년

- 창고 판매가 또는 특정 전리품 가치 보정
- 경제 효과는 기존 Base Value 구조를 훼손하지 않고 modifier 방식으로 적용

#### 풍년

- 흉년과 반대 방향의 제한적 경제 보정

#### 상인 방문

- 창고 판매 보정 또는 판매 가능 상태에 간단한 혜택 적용

#### 귀족 의뢰 증가

- 향후 의뢰 자동 생성 시스템에서 사용할 modifier 저장
- 현재 의뢰 생성 구조와 안전하게 연결 가능할 경우에만 실제 효과 적용

#### 국경 분쟁

- 지역 위험도 또는 의뢰 보상 modifier 기반만 준비

#### 전염병

- 모집 확률 또는 운영 관련 modifier 기반 준비
- 현재 모집 시스템과 안전하게 연결 가능한 최소 효과만 적용

---

### 8. 효과 적용 원칙

세계 이벤트 효과는 기존 원본 데이터 값을 직접 영구 변경하지 않는다.

예시

- 전리품 `baseValue` 자체를 수정하지 않음
- 시설 기본 비용을 직접 덮어쓰지 않음
- 의뢰 원본 보상을 영구 수정하지 않음

대신 활성 이벤트를 조회하여
현재 계산 결과에 modifier를 적용한다.

예시 구조

- 판매가 계산 시 활성 세계 이벤트 modifier 확인
- 의뢰 보상 계산 시 활성 세계 이벤트 modifier 확인
- 모집 확률 계산 시 활성 세계 이벤트 modifier 확인

이벤트 종료 후에는 modifier가 자동으로 사라져야 한다.

동일 계산식을 UI와 게임 로직에 중복 작성하지 않는다.

---

### 9. 활성 이벤트 관리

GameState에 현재 활성 중인 세계 이벤트를 저장한다.

예시

```ts
activeWorldEvents: ActiveWorldEvent[];
```

현재 프로젝트의 정규화 원칙에 따라 Record가 더 적합하다면
기존 구조를 우선한다.

필요 시 종료된 이벤트의 간단한 기록도 보존한다.

예시

- 최근 세계 이벤트 기록
- 시작일
- 종료일
- 지속 기간
- 주요 효과

완료된 세계 이벤트를 무조건 삭제해
향후 연대기 확장이 불가능해지는 구조는 피한다.

---

### 10. 하루 시작 알림

현재 별도의 ‘하루 시작’ 화면이 없다면
새로운 대형 시스템을 만들지 않는다.

기존 `DayEndOverlay`의 보고서 단계 또는
다음 날 진입 직후 표시되는 간단한 알림 패널을 재사용한다.

알림 대상

- 오늘 새로 발생한 세계 이벤트
- 오늘 종료된 세계 이벤트
- 현재 활성 중인 주요 세계 이벤트

표시 정보

- 이벤트 이름
- 간단한 설명
- 지속 예상 기간
- 현재 적용 효과 요약

기능 확인이 가능한 최소 UI면 충분하다.

복잡한 연출, 컷신, 선택지는 구현하지 않는다.

---

### 11. 일일 운영 보고서 연동

기존 `DailyReport` 구조와 자연스럽게 연동한다.

필요 시 `DailyReportItem` 종류에 다음 항목을 추가한다.

- `world_event_started`
- `world_event_ended`

정확한 식별자는 기존 명명 규칙에 맞게 조정한다.

기존 보고서 항목 정렬과 UI를 깨뜨리지 않는다.

세계 이벤트 시작·종료가 길드 연대기에 기록되는 경우,
기존 `ChronicleCategory = "world"`를 우선 활용한다.

---

### 12. 디버그 및 테스트 지원

개발 중 세계 이벤트를 검증할 수 있도록
최소한의 재현 방법을 제공한다.

가능한 방법

- 개발 모드에서 특정 이벤트 강제 발생 함수
- 고정 시드 또는 deterministic roll
- DevPanel에 활성 이벤트 목록 표시
- 콘솔 로그

기존 DevPanel이 있다면 필요한 최소 항목만 추가한다.

일반 플레이 UI에 개발용 버튼을 노출하지 않는다.

## 기본 이벤트 초기 설계

### 왕국 축제

- 종류: 축제
- 기본 지속 기간: 짧음
- 예상 효과: 창고 판매 보정
- 중복: 불가

### 몬스터 증가

- 종류: 위협
- 기본 지속 기간: 중간
- 예상 효과: 몬스터·위험 관련 modifier
- 중복: 불가

### 흉년

- 종류: 경제/재난
- 기본 지속 기간: 김
- 예상 효과: 판매가 또는 특정 자원 가치 보정
- 풍년과 동시 활성화 금지

### 풍년

- 종류: 경제
- 기본 지속 기간: 김
- 예상 효과: 일부 경제 modifier
- 흉년과 동시 활성화 금지

### 상인 방문

- 종류: 방문
- 기본 지속 기간: 매우 짧음
- 예상 효과: 창고 판매 혜택
- 중복: 불가

### 귀족 의뢰 증가

- 종류: 의뢰
- 기본 지속 기간: 중간
- 예상 효과: 의뢰 생성 modifier
- 현재 의뢰 생성 시스템 범위 내에서만 안전하게 연결

### 국경 분쟁

- 종류: 분쟁
- 기본 지속 기간: 중간
- 예상 효과: 위험도·의뢰 보상 modifier 기반
- 대형 전쟁 시스템은 구현하지 않음

### 전염병

- 종류: 재난
- 기본 지속 기간: 중간
- 예상 효과: 모집 또는 운영 modifier 기반
- 부상·질병 확산 시뮬레이션은 구현하지 않음

## 데이터 구조

필요한 타입을 추가한다.

예시

```ts
type WorldEventType =
  | "festival"
  | "monster_surge"
  | "famine"
  | "abundant_harvest"
  | "merchant_visit"
  | "noble_quest_boom"
  | "border_conflict"
  | "epidemic";

interface WorldEventDefinition {
  id: EntityId;
  type: WorldEventType;
  name: string;
  description: string;
  weight: number;
  minDurationDays: number;
  maxDurationDays: number;
  conflictGroup?: string;
  effects: WorldEventEffect[];
}

interface ActiveWorldEvent {
  id: EntityId;
  definitionId: EntityId;
  startedAt: GameDate;
  remainingDays: number;
}
```

위 코드는 예시이며,
기존 `EntityId`, `GameDate`, 상태 관리 방식과 명명 규칙을 우선한다.

## 파일 위치 원칙

현재 프로젝트 구조에 맞춰 다음 역할을 분리한다.

예시

- 세계 이벤트 타입: 기존 공용 게임 타입 파일
- 이벤트 정의 데이터: `src/data/` 또는 적절한 세계 이벤트 데이터 파일
- 발생·진행·종료 로직: `src/game/simulation/`
- 계산 modifier: 관련 selector 또는 simulation 공통 함수
- UI: 적절한 feature 폴더
- 레이블: 기존 labels 파일

정확한 경로는 현재 구조를 먼저 확인한 뒤 결정한다.

### BRIEFING

관련 BRIEFING 문서를 확인한다.

적절한 문서가 있다면 업데이트한다.

없다면 필요 시

를 생성한다.

BRIEFING에는 현재 구현 목록을 반복하기보다
향후 확장 방향과 세계 이벤트 철학을 기록한다.

예시

- 지역별 사건
- 국가별 사건
- 세력 관계 변화
- 연쇄 이벤트

- 대형 재난
- 레이드 발생
- 세계지도 변화
- 장기 경제 변화
- 세계 연대기 연동

미구현 기능을 구현 완료로 기록하지 않는다.

## 구현 원칙

- 기존 시스템을 최대한 재사용한다.
- 관련 없는 기능은 수정하지 않는다.
- 구현 범위를 불필요하게 확장하지 않는다.
- 세계 이벤트 정의와 활성 인스턴스를 구분한다.
- 원본 데이터를 영구 수정하지 않고 modifier 방식으로 효과를 적용한다.
- 이벤트 종료 후 효과가 남지 않도록 한다.
- 랜덤 결과는 가능한 한 기존 결정적 처리 또는 재현 가능한 방식과 조화를 이루도록 한다.
- 하루 처리 중 동일 이벤트가 중복 생성되지 않도록 한다.
- 기존 Quest Event Engine과 World Event System을 혼동하지 않는다.
- Quest Event는 개별 의뢰 진행 사건이고, World Event는 길드 외부 세계 상태 변화다.
- 미구현 기능을 편의상 추가하지 않는다.

---

## 금지 사항

- 기존 의뢰 이벤트 `EVENT_POOL`에 세계 이벤트를 혼합하지 않는다.
- 기존 Adventure Log 이벤트를 세계 이벤트 저장소로 사용하지 않는다.
- 전리품 Base Value를 세계 이벤트 발생 시 직접 덮어쓰지 않는다.
- 길드 골드를 이벤트 효과로 직접 임의 수정하지 않는다.
- 매일 반드시 이벤트가 발생하도록 강제하지 않는다.
- 여러 이벤트가 무제한으로 동시에 발생하도록 만들지 않는다.
- 상반된 이벤트를 동시에 허용하지 않는다.
- 기존 `processDayEnd` 흐름을 대규모로 재작성하지 않는다.
- 관련 없는 UI 개편을 하지 않는다.
- 새로운 아이디어를 임의 구현하지 않는다.
