# 0020-C — 가입 신청 시스템 확장 및 연출 리뉴얼

**버전**: 0020-C  
**상태**: todo

---

# 작업 목적

0019-I에서 모든 가입 신청자를 고유한 이벤트를 가진 인물로 변경하였다.

이번 업데이트에서는 가입 신청을 Guild Chronicle의 대표 콘텐츠로 발전시킨다.

목표는 단순한 지원자 목록이 아니라 **'한 사람과의 만남'** 을 플레이어가 경험하도록 만드는 것이다.

---

# 설계 철학

- 모든 지원자는 기억에 남는 한 사람이다.
- 가입 신청은 UI가 아니라 하나의 짧은 이야기다.
- 플레이어는 사람을 채용하는 것이 아니라 인연을 선택한다.
- 명성은 누가 찾아오는가에 영향을 줄 수 있지만, 얼마나 많이 찾아오는가는 결정하지 않는다.

> **중요 원칙**
>
> 가입 신청 이벤트는 가능한 한 여러 번 보더라도 기억에 남을 수 있도록,
> 템플릿 수준의 짧은 문장이 아니라 **작은 이야기(Short Story)** 형태로 작성한다.

---

# 구현 범위

## 1. 가입 신청 이벤트 확장

기존 이벤트 구조를 유지하면서 데이터만 추가하여 쉽게 확장 가능한 구조를 유지한다.

예시

- 라이벌
- 스승
- 제자
- 형제
- 연인
- 왕실 추천
- 귀족 가문
- 몰락한 기사
- 은퇴한 모험가
- 유명 파티 해산
- 멸망한 길드 생존자
- 어린 천재
- 늦깎이 모험가

---

## 2. 가입 신청 등장 연출

지원자가 생성되면 바로 상세 화면을 열지 않는다.

예시 연출

- 누군가 길드의 문을 두드립니다.
- 왕실 마차가 길드 앞에 멈춰 섭니다.
- 폭우 속에서 여행자가 문을 두드립니다.
- 두 명의 모험가가 함께 찾아왔습니다.

연출 후 Inbox를 통해 가입 신청 화면으로 이동한다.

---

## 3. 가입 신청 UI 전면 리뉴얼

기존 정보 나열형 UI를 이야기 중심 UI로 변경한다.

포함 요소

- 대형 초상화
- 이름 강조
- 직업 강조
- 가입 배경 카드
- 현재 상황 카드
- 추천인 카드
- 첫인상 카드
- 장점 카드
- 단점 카드
- 지원 동기 카드

---

## 4. 이벤트별 분위기

이벤트 종류에 따라 분위기를 다르게 표현한다.

예시

- 왕실 추천
- 귀족 가문
- 형제
- 연인
- 부상당한 지원자

공통 레이아웃을 유지하면서 강조 요소만 변경한다.

---

## 5. 후속 이벤트 구조

가입 이후 연결 가능한 구조를 마련한다.

예시

- 추천인 방문
- 라이벌 등장
- 가족 방문
- 과거 동료 등장
- 길드원의 반응

이번 작업에서는 구조만 마련하며 대량 구현은 하지 않는다.

---

## 6. 발생 구조

가입 신청은 세계의 변화와 사건으로 이어지는 특별한 만남으로 설계한다.

향후 연결 대상

- 명성
- 세계 이벤트
- 추천
- 특별 의뢰
- NPC 관계

---

## 7. Inbox 연동

가입 신청 발생 시 Inbox 등록.

클릭하면 해당 지원자의 화면으로 이동한다.

---

# 데이터 구조

예시

```ts
interface RecruitmentStory {
  title: string;
  introduction: string;
  background: string;
  currentSituation: string;
  motivation: string;
  firstImpression: string;
  strengths: string[];
  weaknesses: string[];
}
```

기존 RecruitmentEventDefinition을 우선 재사용한다.
