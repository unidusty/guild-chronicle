# 05. PROJECT STATUS

## 현재 버전

**005 — 모험가 랜덤 생성 및 영입 프로토타입**

## 완료

- 001 프로젝트 기획 기반
- 002 Vite + React + TypeScript 실행 프로젝트
- PC 경영 시뮬레이션형 길드 대시보드
- 공용 게임 엔티티 타입 정의
- 길드, 모험가, 직업, 부상, 파티, 의뢰, 지역, 시설, 연대기, 결재 데이터 구조
- ID 참조 기반의 정규화된 `GameState` 구조
- 화면용 데이터를 계산하는 selector 분리
- `ko-KR` 기준 자금과 명성 숫자 표시
- 기존 대시보드를 단일 게임 상태 데이터와 연결
- `tools/generate-manifest.js` — 에셋 폴더 스캔 및 매니페스트 자동 생성
- `src/generated/assetManifest.ts` — 초상화 목록 (dev/build 시 자동 갱신)
- `src/game/assets/portraits.ts` — 종족·성별별 초상화 조회 및 플레이스홀더 처리
- 기본 에셋과 모드 에셋 분리 구조, 초상화 ID 전역 유일성 보장
- `src/game/generator/` — 모험가 랜덤 생성 로직 (names, traits, stats, adventurer)
- 직업별 핵심 능력치 편향, 종족별 소편향, 잠재력 등급(S/A/B/C/D)
- 영입 후보 3인 카드 UI (능력치 바, 잠재력, 특성, 소속감)
- 영입 인터랙션: 1명 영입 → roster 즉시 반영 → 나머지 비활성화
- 새 후보 찾기로 3명 재생성 (기존 ID와 충돌 없음)
- `GameState` 를 React state로 전환 (useState)

## 현재 데이터 원칙

- 화면 표시용 문자열을 원본 데이터에 중복 저장하지 않는다.
- 엔티티 간 연결은 이름이 아니라 안정적인 ID를 사용한다.
- 원본 게임 상태와 UI 가공 데이터를 분리한다.
- 사망, 은퇴, 이탈한 모험가는 `isArchived`와 연대기로 보존한다.
- 저장 데이터 버전을 관리한다.
- 초상화 경로와 개수를 코드에 하드코딩하지 않는다.
- 랜덤 생성 로직은 UI와 완전히 분리한다.

- 저장과 하루 진행 버튼은 UI만 있고 동작하지 않는다.
- 새로고침 시 영입 결과가 초기화된다 (저장 미구현).
- 파티 인원과 의뢰 성공 계산식은 추후 밸런스 단계에서 확정한다.
- 초상화를 추가한 뒤에는 `npm run manifest`를 실행해야 반영된다.
