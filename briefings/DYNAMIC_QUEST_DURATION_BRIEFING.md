# DYNAMIC QUEST DURATION BRIEFING

## 핵심 철학

의뢰 기간은 약속이 아니라 예측이다.

출발 전에 세운 계획은 현장의 실제 상황 앞에서 무너질 수 있다.
폭우가 이동을 막고, 경로가 붕괴되고, 지원 파티가 늦게 합류한다.
반대로 현지 주민이 단서를 제공하거나, 오래된 지도가 지름길을 알려주기도 한다.

Guild Chronicle의 동적 의뢰 기간 시스템은
파티의 귀환이 예상보다 늦거나 빨라질 때
그 변화가 실제 사건과 길드장의 결정에 근거하도록 만든다.

---

## 설계 방향

### 최초 예상은 불변이다

의뢰 카드에 표시된 기간은 최초 예상값이다.
이 값은 의뢰가 끝날 때까지 변경되지 않는다.

실제 기간이 얼마나 늘거나 줄었는지는
최초 예상값과의 비교를 통해서만 파악된다.

### 변경에는 반드시 근거가 있다

기간 변화는 실제 발생한 이벤트 또는 길드장의 결정에서만 나온다.

무작위로 기간이 늘어나거나 줄어드는 일은 없다.
폭우 이벤트가 발생했기 때문에 +1일이 추가된다.
지원 파티 파견을 결정했기 때문에 +2일이 추가된다.

### 동일 사건은 한 번만 영향을 준다

같은 이벤트나 결정이 두 번 기간에 반영되지 않는다.
중복 방지 키는 `(sourceType, sourceId)` 조합이다.

### 기간 변경은 제한 안에서만 허용된다

연장은 초기 기간의 50% 또는 최대 10일 중 작은 값을 초과할 수 없다.
단축은 남은 필수 단계 수 + 1 미만으로 내려갈 수 없다.

## 현재 구현 범위 (0019-H)

### 기간 변경 이벤트 (8종)

| 이벤트 | 변화 |
|--------|------|
| ev-env-001 폭우 | +1일 |
| ev-env-002 짙은 안개 | +1일 |
| ev-env-003 낙석 | +1일 |
| ev-env-004 경로 붕괴 | +2일 |
| ev-env-005 갑작스러운 폭설 | +2일 |
| ev-env-006 강물 범람 | +2일 |
| ev-explore-010 오래된 지도 발견 | −1일 |
| ev-person-004 지역 주민 정보 입수 | −1일 |

단축 이벤트는 탐사·인물 카테고리이므로 귀환 단계에서는 발생하지 않는다.

### 지원 파티 파견 연동

지원 결정 시 +2일(SUPPORT_TRAVEL_DAYS)이 1회 적용된다.
이미 지원 파티가 파견된 의뢰에는 중복 적용되지 않는다.

### Quest Director 자동 연동

기간이 변경되면 `prog.totalDays`가 갱신된다.
Quest Director는 이 값을 기준으로 urgency를 즉시 재평가한다.

### 데이터 추적

모든 기간 변경 사건은 `QuestDurationChange` 배열에 누적된다.
각 항목은 변경 전후 예상일, 사유, 단계, 출처 타입과 ID를 포함한다.

### UI 표시 위치

- **진행 중 의뢰 목록** — 기간 변화가 있으면 +N일 / −N일 배지 표시
- **의뢰 상세 패널** — 최초 예상 / 현재 예상 / 최근 변경 사유 블록
- **귀환 보고 모달** — 실제 수행 기간 + 최초 예상 대비 변화 표시

### 의뢰 연대기 및 귀환 보고서 연동

`QuestChronicleEntry`에 최초 예상 / 최종 예상 / 실제 수행 기간을 기록한다.
`ReturnReport`에 실제 수행 기간과 최초 예상 대비 총 변화량을 포함한다.

## 향후 확장 방향

### 날씨 시스템 연동

계절과 지역에 따라 특정 날씨 이벤트 확률이 달라지면
기간 변화가 세계 상황을 반영하게 된다.

### 지역 거리 기반 기간 계산

지역별 이동 거리가 구현되면
최초 예상 기간 자체가 자동으로 산출될 수 있다.

### 의뢰인 반응과 보상 조정

기간 초과 또는 조기 완료가 의뢰인의 평가와 보상에 영향을 줄 수 있다.
지연 위약금, 조기 완료 보너스가 추가될 수 있다.

### 협상과 강행군

기간 연장 여부를 길드장이 직접 협상하거나,
강행군 명령으로 기간을 압축하는 대신 위험도가 올라가는 판단 구조도 가능하다.
