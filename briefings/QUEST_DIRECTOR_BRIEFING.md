# QUEST DIRECTOR — BRIEFING

## 시스템 철학

Quest Director는 단순한 기간 조정기가 아니다.

의뢰가 논리적 흐름을 거쳐 완료되도록 보장하는 **스토리 감독자**다.
플레이어는 파티를 파견하지만, 의뢰가 어떻게 전개될지는
현장에서 올라오는 보고와 길드장의 판단에 달려 있다.

Director는 무대 뒤에서 작동한다.

- 의뢰가 결말 없이 끝나는 것을 막는다
- 이야기의 흐름이 필수 단계를 거치도록 유도한다
- 절박한 상황에서는 강제 이벤트로 플레이어의 결정을 요청한다
- 플레이어가 결정하기 전까지 다음 날로 넘어갈 수 없다

---

## 설계 원칙

### 1. 이벤트가 아닌 흐름을 관리한다

Director가 관리하는 것은 개별 이벤트가 아니라
의뢰가 완결되기 위해 반드시 거쳐야 하는 **필수 단계 시퀀스**다.

각 의뢰 유형별 필수 단계는 `questValidation.ts`에 정의되어 있다.

예시 — 수색 의뢰:
1. `search-clue` — 단서 확보 (탐사·인물 이벤트로 충족)
2. `search-target` — 목표 발견 (탐사·인물·위험 이벤트로 충족)

### 2. urgency로 개입 강도를 조절한다

| 긴급도 | 조건 | 개입 방식 |
|--------|------|----------|
| none | 필수 단계 모두 완료 | 개입 없음 |
| low | 여유 있음 | 개입 없음 |
| high | 촉박 | 관련 이벤트 가중치 증가 |
| critical | 귀환 전 완료 불가 | 강제 이벤트 생성 |

### 3. 선택은 길드장의 몫이다

Director가 강제 이벤트를 생성해도
그 이벤트에 어떻게 대응할지는 길드장이 결정한다.

강제 이벤트는 Inbox에 등록되고,
길드장이 선택하기 전까지 해당 의뢰는 일시 정지된다.

## Mandatory Flow 보호

새 이벤트가 추가되어도 다음 규칙은 변경되지 않는다.

- 필수 단계를 대체할 수 있는 이벤트는 명확히 정의된다
- 기간 단축으로 필수 단계를 생략할 수 없다
- 철수 선택 시 기존 철수 흐름을 사용한다
- critical 강제 이벤트는 Inbox 등록 없이 자동 진행되지 않는다
- 결정 대기 중에는 해당 의뢰의 다음 날 진행이 차단된다

## 향후 확장 예정

다음 항목은 이번 작업에서 구현하지 않았다.

### 선택지 구조 확장

- `QuestDecisionOption` — 선택지별 예상 효과·실제 효과·위험도
- `QuestDecisionEffect` — 기간·위험도·성공률·보상 modifier
- `QuestDecisionOutcome` — 선택 결과 후속 이벤트 연결

### 선택 결과 → 게임 상태 영향

- 기간 modifier (우회: +2일, 강행: ±0)
- 위험도 modifier (야영: 감소, 야간 이동: 증가)
- 성공률 modifier (정보 확보: +, 식량 부족 방치: -)
- 보상 modifier (추가 탐사: +, 철수: 없음)

### 후속 이벤트 확장

- 우회 선택 → 숨겨진 길 발견
- 야영 선택 → 야간 습격
- 추가 탐사 → 희귀 발견 또는 강적 조우
- 지원 요청 → 지원 파티 도착

이 항목들은 현재 `followUpIds` 구조로 일부 지원되며,
향후 선택 결과와 실제 연결하는 작업에서 완성된다.
